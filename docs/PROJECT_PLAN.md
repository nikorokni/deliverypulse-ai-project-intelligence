# Project Delivery Plan

## Delivery approach

The MVP uses four short milestones with a demo and acceptance checkpoint at the end of each milestone.

| Milestone | Scope | Exit criteria |
|---|---|---|
| 1. Discovery | Users, problem, product principles, KPI tree | PRD and MVP boundary agreed |
| 2. Decision model | Confidence score, scope scenarios, risk model | Scenarios produce explainable outcomes |
| 3. Experience | Command centre, delivery, risks, roadmap | Responsive interactions pass review |
| 4. Release | Documentation, CI, deployment, portfolio packaging | Build passes and live demo is available |

## RAID summary

### Risks

- Confidence score may be treated as objective truth rather than a decision aid.
- Poor source data can create misleading precision.
- Teams may optimise velocity instead of customer outcomes.

### Assumptions

- Source tools provide consistent status, ownership and date fields.
- Users agree on shared definitions for blocked work and release scope.
- Portfolio leaders retain accountability for final decisions.

### Issues

- Demo uses representative data rather than a live delivery-system integration.

### Dependencies

- Source-system APIs for a future connected version
- Identity and permissions model for multi-tenant use
- Historical release data for model calibration

## Governance cadence

- Daily: automated signal refresh
- Twice weekly: delivery-risk triage
- Weekly: release decision review
- Monthly: KPI and model-calibration review
